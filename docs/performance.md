# Производительность: замеры до и после (CLAUDE.md, раздел 12)

Замеры — 1 октября 2026. **Реальные устройства из раздела 13 пока не проверялись:** ниже —
ближайшие доступные эмуляции. Перед запуском нужна проверка на Windows (встроенная графика),
iPhone (текущее и −2 поколения, режим энергосбережения), Android среднего класса трёхлетней давности.

## Как мерили

| Что              | Чем                                                                                    |
| ---------------- | -------------------------------------------------------------------------------------- |
| Десктоп high     | Chromium + Metal (Apple M1 Pro), 1920×1080 @2x (бюджет 3,5 Мп → DPR 1,3), уровень high |
| Телефон medium   | эмуляция 390×844 @3x, CPU ×4; сеть — медленный 4G (1,6 Мбит/с, 150 мс) для LCP/CLS/INP |
| fps, худший кадр | `requestAnimationFrame` 4 с в покое и 4 с колесом по дорожке главы                     |
| JS на кадр       | профиль процессора (CDP), только работа главного потока                                |
| GPU на кадр      | fps без vsync и без ограничения частоты: кадр упирается в видеокарту → 1000 / fps      |
| LCP, CLS, INP    | Lighthouse (настоящее замедление) и PerformanceObserver в Playwright                   |
| Вес              | байты по сети (CDP)                                                                    |

Важно: `?debug` и флаг `--enable-precise-memory-info` сами дают зависания по 1–3 с —
в первой версии таблицы «до» они были приняты за проблемы сайта. Цифры ниже — без них.
Встроенный GPU-таймер (EXT_disjoint_timer_query) на Metal завышает время (12–19 мс при
fps 110+) — вместо него fps без vsync.

## Что найдено и исправлено (только то, что показали замеры)

1. **Первый кадр нескомпилированной сцены.** Сцена следующей главы попадала в кадр раньше, чем
   её шейдеры успевали скомпилироваться в простое, — синхронная компиляция, кадр 40–80 мс.
   Теперь сцена рисуется только после `compileAsync` (Stage, `shown`).
2. **Синхронная проверка шейдеров** (`getProgramInfoLog`, процессор ждёт видеокарту) — в продакшене
   выключена, в `?debug` остаётся.
3. **Видео коня декодировалось всегда**, даже когда «Рассвет» далеко, и заранее загруженные
   клипы играли все сразу. Теперь играет только текущий клип и только пока коня видно.
4. **Рендер в статике.** На брифе, в футере и текстовых блоках без сцены кадр всё равно рисовался.
   Теперь — один пустой кадр и стоп (`canvas/onScreen.ts`); e2e — `e2e/perf.spec.ts`.
5. **Аллокации в кадре:** `matchMedia` в кадре (рассвет, кадры архива), массивы униформ
   (волна, центр рельефа, шум зерна, полоса «света», cover кадров), объект сдвигов камеры,
   состояние рассвета — теперь пишутся в одни и те же объекты.

## Проверено, менять не нужно

- **Инстансинг:** трава (стебли и карточки) и мебель «Дня» — instanced; draw calls ≤ 110.
- **Бюджет пикселей на 4K:** ≤ 3,5 Мп high / 2 Мп medium (тест `capabilities.test.ts`, 3840×2160).
- **Анимации от delta:** ticker даёт `dt` в секундах, не больше 0,1 с; `Date.now` в анимациях нет.
- **will-change:** только у «солнца» навигации-горизонта (движется всегда — держать постоянно верно).
- **Бандл:** three.js, R3F, GSAP, Spark — только динамическими импортами после `load`;
  первый экран (DOM) их не ждёт (`next experimental-analyze`, `route-bundle-stats.json`).
- **`setSize` в профиле** — ошибка привязки сэмплов: в покое буфер холста не пересоздаётся (0 раз за 3 с).

## Что не соблюдено и почему

- **TBT в Lighthouse 215–350 мс (рекомендация Lighthouse — ≤ 200).** В окно TBT попадает запуск 3D
  в простое после `load` (three.js, сцена, первый кадр — задачи по 95–150 мс на CPU ×4).
  Порог раздела 12 — **INP ≤ 200 мс** — соблюдён и во время запуска 3D (80–96 мс, один раз 192 мс
  при нажатии во время гидрации). В Lighthouse CI
  TBT — предупреждение, не ошибка. Следующий шаг, если понадобится: дробить создание сцены «Рассвета»
  на несколько задач.
- **`renderMs` (время вызова рендера) вырос на 0,5–1 мс в поздних главах.** Это не работа процессора
  (профиль: 0,5–0,6 мс/кадр), а ожидание ответов видеокарты внутри вызовов WebGL; на длину кадра
  не влияет (худший кадр 16,8 мс). Наблюдаем.
- **Lighthouse в режиме модели (Lantern) на localhost даёт LCP 3,7 с** при наблюдаемом 0,1 с:
  модель считает условием первой отрисовки всё, что успело скачаться до неё на быстром localhost.
  В CI — настоящее замедление (`throttlingMethod: devtools`).
