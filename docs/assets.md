# Ассеты: требования для 3D-художника и видеографа

Документ для тех, кто готовит модели, рендеры и съёмку для сайта ULY DALA (CLAUDE.md, разделы 6, 12, 17).
Сейчас в проекте лежат **процедурные заглушки с финальными именами узлов**: ваши файлы заменяют их
один к одному, код менять не нужно.

## Как отдать файл

1. Положите исходник в `assets-src/models/<имя>.glb` (модели) — имя файла как в таблице ниже.
2. Разработчик запускает `npm run assets` — конвейер сожмёт геометрию и текстуры и положит
   результат в `public/assets/models/<имя>.high.glb` и `<имя>.medium.glb`.
3. CI проверит бюджеты размера. Превышение — сборка красная, файл нужно облегчить.

## Система координат и масштаб

| Параметр      | Значение                                                                                 |
| ------------- | ---------------------------------------------------------------------------------------- |
| Единицы       | **1 единица = 1 метр**                                                                   |
| Оси           | glTF 2.0: **Y — вверх**, правосторонняя система, камера смотрит по **−Z**                |
| Пивот модели  | в центре основания (юрта — центр круга на уровне земли; дастархан — центр стола на полу) |
| Земля         | Y = 0                                                                                    |
| Формат        | glTF 2.0 binary (`.glb`), материалы PBR metallic-roughness                               |
| Трансформации | применены (scale = 1, rotation = 0 у корня), без отрицательных масштабов                 |

Высота камеры в степи — 0,6–1,8 м. Первый экран снят «объективом» 135 мм с 60 см над землёй.

## Имена узлов (контракт с кодом)

Имена — латиница, `snake_case`, ровно как в таблице. Код находит части по этим именам
(сборка юрты по скроллу, смыкание дастархана, экран LED).

| Файл             | Узлы                                                                                                           | Где на сайте                                 |
| ---------------- | -------------------------------------------------------------------------------------------------------------- | -------------------------------------------- |
| `yurt.glb`       | `kerege` — решётчатые стены · `uyki` — купольные жерди · `shanyrak` — венец · `kiiz` — войлок · `esik` — дверь | Глава 2 «Сборка»: детали приходят по очереди |
| `horse.glb`      | `horse_plane` — плоскость под видео коня, UV 0…1 на весь кадр, низ плоскости — земля                           | Глава 1 «Рассвет»                            |
| `dastarkhan.glb` | `dastarkhan_left`, `dastarkhan_right` — две половины ткани · `dastarkhan_table` — стол                         | Главы 3–4: кудалык, «Огонь»                  |
| `led_wall.glb`   | `led_frame` — рама · `led_screen` — экран (UV 0…1, контент подставляется кодом)                                | Глава 3: конференция в шатре                 |

### Юрта (глава 2 «Сборка»)

- `kerege` и `uyki` можно отдать **одним мешем** каждый (так дешевле). Код сам режет их по углу
  вокруг оси юрты: кереге — на 4 панели-гармошки (стык панелей — у двери), уықи — на **48 жердей**
  (жердь i стоит на угле i · 7,5°, начиная с +X). Другое число жердей — сообщить разработчику
  (`POLE_COUNT` в `src/canvas/assembly/timeline.ts`).
- Дверной проём — спереди, по **+Z** (к камере), шириной ~1 м: в `kerege` и в стене `kiiz` там пусто,
  купол `kiiz` — целый. Камера в финале входит внутрь через этот проём.
- `esik` — дверь в проёме; петля — по левому краю (−X), открывается наружу. Пивот ставит код.
- `kiiz` виден и снаружи, и изнутри (двусторонний материал). Анимация войлока — **VAT**
  (Vertex Animation Texture) от художника: одна дорожка 0…1 «войлок укрывает каркас сверху вниз».
  Пока VAT нет — шейдерная заглушка с тем же параметром.
- Внутри стоит своя техника: LED-экран у дальней стены, два световых прибора на стойках,
  две колонки (сейчас — процедурные заглушки в `src/canvas/assembly/tech.ts`). Модели — отдельным
  файлом `tech.glb` (узлы `tech_led`, `tech_light_left`, `tech_light_right`, `tech_speaker_left`,
  `tech_speaker_right`), когда будут готовы.
- Материалы — диэлектрики (**metallic = 0**), если это не металл на самом деле: без карты окружения
  металл выглядит чёрным.

### Площадки «Дня» (глава 3)

Шесть площадок стоят в той же степи вдоль пути камеры; камера смотрит на каждую с −X на +X,
правая часть кадра — +Z (слева — текст главы). Пока все площадки — процедурные заглушки
(`src/canvas/day/setups.ts`) с финальной компоновкой; модели заменят их по одной.

| Площадка         | Что нужно от художника                                                                                                |
| ---------------- | --------------------------------------------------------------------------------------------------------------------- |
| Конференция      | Шатёр ~5,4 × 6 м, открыт к камере; внутри `led_wall.glb`, ряды стульев, трибуна                                       |
| Кофе-брейк       | Стол под скатертью, фарфор (чашки, блюдца), медные кофейники; пар — частицы в коде                                    |
| Тимбилдинг       | Разметка поля (верёвка, колышки с лентами) — открытая степь, модели минимальны                                        |
| Кудалык          | Белая ткань двумя половинами (`dastarkhan_left/right`) с **VAT** «смыкания»; руки и предметы — VAT или видео с альфой |
| Свадьба          | Длинный стол, стулья, свечи, гирлянда тёплых ламп                                                                     |
| Частный праздник | Невысокий стол, подушки, фонари, небольшая юрта позади                                                                |

- В кадре кудалыка — **только руки и предметы**, людей и лиц нет. Пока рук нет: предметы
  ставятся «как руками» (по дуге, с посадкой settle).
- Металл (медь, хром) и фарфор отражают env map (RoomEnvironment → PMREM, считается в коде);
  остальным материалам карта окружения не нужна.
- Контент LED-экрана — код (шейдер-заглушка «слайда»); реальные слайды — `TODO(client-data)`.
- Под площадками трава скошена (круги в шейдере травы), низкая мебель не тонет в ковыле.
- Презентация «Скачать презентацию» — пока PDF-заглушка (`scripts/generate-pdf-stub.mjs`);
  настоящая — от заказчика, на трёх языках, со встроенными шрифтами (кириллица).

### «Огонь» (глава 4)

Очаг и дастархан стоят в той же степи; камера — от макро у очага к ортогональному виду сверху
(`src/canvas/fire/camera.ts`). Заглушки — `src/canvas/fire/hearth.ts`, `src/canvas/fire/table.ts`.

| Что              | Требование                                                                                                   |
| ---------------- | ------------------------------------------------------------------------------------------------------------ |
| Очаг             | Камни по кругу ~0,9 м, угли — отдельным мешем (свечение и шум делает шейдер), пивот — центр очага            |
| Казан            | Чугун, ~0,6 м в диаметре, на подставке; внутри — поверхность бульона; хорошо читается сверху                 |
| Дым              | Flipbook 8×8 с альфой (или оставляем частицы), тёплый серый, без «мультяшных» колец                          |
| Капля            | Остаётся процедурной: стекает по стенке казана и испаряется (пар)                                            |
| Посуда и блюда   | Модели по списку сетов (`src/content/menu.ts`): кофе-брейк, банкет, традиционный — читаются сверху, как план |
| Ковёр под столом | Тёмный войлок ~7,4 × 3,9 м — «лист» плана                                                                    |

- Состав блюд и описания — `TODO(client-data)`: меню подтверждает шеф.
- Свет очага — точечный источник в сцене с самого начала (сила 0 до «Огня»): его появление
  не должно пересобирать шейдеры. Ночью общий свет гаснет, главный свет — огонь.

## UV и текстуры

- **UV0** (`TEXCOORD_0`) — для текстур материала, 0…1.
- **UV1** (`TEXCOORD_1`) — для лайтмап: без перекрытий, отступ между островами ≥ 4 px на 1024.
- UV сохраняются, даже если у материала в файле нет текстуры (видео и экран назначаются кодом).
- Размеры текстур — степени двойки, **не больше 2048** (high); medium конвейер уменьшит до 1024 сам.
- Цвет (`baseColor`, `emissive`) — sRGB. Нормали — **OpenGL (+Y)**, tangent space, линейные.
- Occlusion / roughness / metalness — одной картой **ORM** (R — AO, G — roughness, B — metal).
- Сжатие делает конвейер: цвет и эмиссия → KTX2 ETC1S, нормали → KTX2 UASTC, геометрия → meshopt
  и квантизация. Присылайте несжатые PNG/JPG внутри `.glb`.

## Лайтмапы по этапам сборки юрты

Юрта освещается запечёнными лайтмапами и **одним** динамическим светом (раздел 6).
Сборка идёт в четыре этапа, свет внутри меняется — нужно четыре лайтмапы в UV1:

| Этап | Что стоит                                             | Файл лайтмапы          |
| ---- | ----------------------------------------------------- | ---------------------- |
| 1    | `kerege`                                              | `yurt_lightmap_stage1` |
| 2    | + `uyki`                                              | `yurt_lightmap_stage2` |
| 3    | + `shanyrak`                                          | `yurt_lightmap_stage3` |
| 4    | + `kiiz`, `esik` (юрта закрыта, свет — через шаңырақ) | `yurt_lightmap_stage4` |

Лайтмапы — отдельными текстурами в `.glb` (материал `yurt_lightmap`, не назначенный мешам),
HDR-исходники — EXR 16 бит, до 2048 × 2048. Код ставит лайтмапу этапа на его границе — там, где
детали встают на место и свет в любом случае меняется (`applyStageLightmap`,
`src/canvas/assembly/materials.ts`). Пока лайтмап нет — юрта на динамическом свете.

## Видео коня (глава 1)

| Параметр     | Требование                                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------------------------- |
| Длительность | **8–12 с, бесшовная петля** (первый и последний кадр стыкуются)                                            |
| Кадр         | Конь в три четверти мордой **влево**, тёмно-гнедой; голова и шея пересекают горизонт                       |
| Свет         | Контровой: солнце на 1° ниже горизонта за конём, контур очерчен светом; пар дыхания каждые 4–5 с           |
| Альфа        | Да, фон прозрачный; пар — полупрозрачный                                                                   |
| Цвет         | **Без тонмаппинга** (Standard / линейный → sRGB, не Filmic / AgX): AgX сайт применяет сам, один раз на всё |
| Мастер       | ProRes 4444 с альфой, 3840 × 2160, 24 или 25 к/с                                                           |
| Пропорции    | 16:9 (плоскость `horse_plane` — 4,8 × 2,7 м)                                                               |

Из мастера делаются четыре файла (имена — как у тестового видео, с `horse` вместо `horse-test`):

```bash
# Safari (и все браузеры на iOS): HEVC + alpha — на Mac, встроенным avconvert
avconvert -s horse-master.mov -o horse.high.mov  -p PresetHEVC3840x2160WithAlpha
avconvert -s horse-master.mov -o horse.medium.mov -p PresetHEVC1920x1080WithAlpha
# Остальные браузеры: VP9 + alpha WebM — ffmpeg с libvpx
ffmpeg -i horse-master.mov -c:v libvpx-vp9 -pix_fmt yuva420p -b:v 8M -auto-alt-ref 0 horse.high.webm
ffmpeg -i horse-master.mov -vf scale=1920:-2 -c:v libvpx-vp9 -pix_fmt yuva420p -b:v 3M -auto-alt-ref 0 horse.medium.webm
```

И **постер** `horse.poster.png` — первый кадр с альфой (показывается, если браузер запретил автоплей).
Проверка: `/ru/render-test` в Safari и Chrome — «без ореолов: да».

> Бюджет первой сцены — 2,5 МБ (раздел 12). 10 секунд 4K с альфой в него не помещаются —
> размер финального видео нужно согласовать заранее (TODO(client-data): решение по бюджету).

## Небо и дальний план

Офлайн-рендер, **запечённые карты под несколько времён суток**, шейдер смешивает их по главам:
05:30 (рассвет), 07:00, 12:00, 18:00, 22:00 (ночь) и снова 05:30.

- Равнопромежуточная проекция (equirect) 4096 × 2048 для high, 2048 × 1024 для medium.
- HDR-исходник EXR 16 бит; горы и дальний план — в той же карте.
- Тёплая полоса у горизонта ~3200 K, выше — холодный индиго ~9000 K (раздел 2).
- Полосы на градиенте убирает дизеринг сайта; не добавляйте шум в карту.

## Ткань и войлок — VAT

Движение ткани (войлок `kiiz`, белая ткань дастархана) — **Vertex Animation Texture**:

- Houdini Labs VAT 3.0, режим Soft Body (или аналог из Blender).
- Две текстуры EXR 16 бит: позиции и нормали; ширина — число вершин (≤ 2048), высота — число кадров.
- JSON с границами (`bounds min/max`), числом кадров и fps.
- Меш — в `.glb` с UV2 (`TEXCOORD_2`) = индекс вершины в текстуре.

## Фазенда — Gaussian Splatting

Только для уровня high и не на iOS (раздел 6). Остальным — видео облёта и фото.

- Съёмка по зонам фазенды (3–4 зоны с остановками камеры, глава 5).
- Исходник — 3DGS `.ply` (формат INRIA), выровненный по миру сайта: Y вверх, 1 ед. = 1 м,
  начало координат — центр главной площадки.
- Разработчик сожмёт в `.spz`; ориентир по размеру — до 30 МБ на зону (грузится в главе 5,
  по бюджету «любая другая глава ≤ 4 МБ» стартовый объём — только ближняя зона).
