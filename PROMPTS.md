# ULY DALA — промпты для Claude Code

## Как пользоваться

1. Создай пустую папку проекта, положи в её корень файл `CLAUDE.md`.
2. Открой папку в Claude Code.
3. Давай промпты строго по порядку, по одному. К следующему — только когда выполнены
   критерии приёмки предыдущего и сделан коммит.
4. После промпта 5 у тебя уже рабочий сайт с формой заявок (без 3D).
   Всё дальше — улучшение, которое не имеет права ломать то, что работает.
5. Если сессия прервалась — начни новую фразой:
   «Прочитай CLAUDE.md и git log, скажи, на каком шаге мы остановились.»

Каждый промпт начинается одинаково: агент сначала изучает, потом меняет.

## Промпт 6. Ядро движения

```
Прочитай CLAUDE.md (раздел 5). Следуй протоколу. Найди все временные rAF и таймеры.

1. src/motion/ticker.ts: единственный requestAnimationFrame. Приоритеты:
   input → progress → timeline → damping → render. Пауза при document.hidden.
   delta в секундах, ограничена 0.1.
2. Lenis только на десктопе (lerp 0.09), нативный скролл на тач. Lenis и ScrollTrigger
   синхронизированы и тикают от ticker.
3. src/motion/progress.ts: глобальный прогресс, текущая глава, локальный прогресс,
   скорость. Границы глав — при ресайзе (svh, без дёрганья от адресной строки).
4. src/motion/spring.ts: критически демпфированная пружина для чисел и векторов.
5. src/motion/input.ts: курсор, тач, скорость в нормализованных координатах.
6. src/motion/reveal.ts: «проявление светом» по разделу 5 — градиент слева направо 900 мс,
   запуск по видимости, страховка 1.5 с, в reduced motion — сразу видно.
   Примени ко всем заголовкам и лидам. Текст hero не начинается с opacity 0.
7. Переведи навигацию-горизонт и хедер на ticker/progress. Удали временные rAF.

КРИТЕРИИ: в профайлере ровно один rAF; юнит-тесты spring и progress; анимации
одинаковы при искусственных 60 и 120 Гц (тест с подменой delta); LCP не ухудшился.
```

КРИТЕРИИ: ≥ 58 fps high на десктопе, ≥ 45 medium на среднем смартфоне; ветер от курсора
виден и затухает; LCP ≤ 2.5 с; текст hero — HTML.
